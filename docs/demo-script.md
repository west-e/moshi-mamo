# デモ動画の台本（目標 2分50秒・日本語）

方針: **主役は製品の動作**。スライドは使わず、実際の画面を撮る。数字はテロップで短く出す。
審査の「デモ」観点に合わせ、冒頭15秒で「誰の・どんな課題を・どう解決するか」を言い切る。

> デモ用の会話（`eval/scenarios/demo/`）は撮影のために書いた架空の会話です。動画の中での動作は精度の根拠にならないので、精度は評価の数字（テロップ）で示す。
> 撮影前のリハーサル（Haiku・判定だけ、各5回）: デモ1は5回とも警告なし（単語一致の方式なら赤）。デモ2（息子を名乗る事故の電話）は5回とも、事故の話（発話3）で注意、今日中の示談金（発話5）で強い注意（単語一致の方式は最後まで強い注意に届かない）。
> 判定の指示を直したあと（2026-11-03、開発記録「誤警告の修正」）も、デモ用3本を各3回流して、9/9 が期待どおりだった。
> デモ2は、制作者の祖母が受けたのと同じ型の手口を、完全に架空の内容で書いたもの（実際の通話の再現ではない）。警察を名乗る型はデモ3として残している。

## 撮影の準備
1. `npm run dev:all` で3つのサーバーを起動する（判定・画面・文字起こし）。
2. ブラウザを全画面（1920×1080）で `http://localhost:5173/` を開く。ブックマークバーなどは隠す。
3. 利用者画面の「音を有効にする」を押しておく。
4. 録画は **OBS Studio**（無料）で、画面と**パソコンの音**（チャイム・通話の音声）を一緒に録る。ナレーションは別に録って、編集（Windows 標準の Clipchamp など）で重ねる。
5. 毎回「通話をリセット」してから始める。

### デモ1・デモ2の入力方法（どれか1つ）
- **A. 2人で読み上げてマイクから入力（おすすめ）**: 一番伝わる。相手役と本人役で、台本（[reading-sheet.md](reading-sheet.md) の「デモ用」）を1文ずつ、1秒ほど間をあけて読む。
  - **注意: スピーカーの音（チャイム）をマイクが拾うと、雑音として文字になることがある。** 読み上げる人はヘッドホンを使う（チャイムは OBS でパソコンの音として録る）。
  - 声を出す人には、動画に声が入ることの了承を取る。名前は出さない。
  - マイクでの動作は未検証なので、撮影前に一度通しで試す。
- **B. 架空の録音音声を流す**: 開発画面の「架空の録音音声を流す」で `audio/d1-family-money.wav`（35秒）・`audio/d2-son-accident.wav`（45秒）を選ぶ。合成音声なので少し機械的だが、確実に動く。ファイルがなければ `pwsh scripts/make-fake-call.ps1 eval/scenarios/demo/d2-son-accident.json audio/d2-son-accident.wav` で作り直せる。
- **C. 文字の自動再生**: シナリオを選んで「自動再生」。音声がないので最後の手段。

### 改善の場面（P8）の撮り方
- シナリオ一覧から「P8 通常: 本物のカード会社から、不正利用の確認」を選び、「自動再生」で流す（10発話・約35秒。編集で早送りする）。
- 直したあとのリハーサル（各3回）では、3回とも赤にならず、黄色が最後まで残った。撮影前にもう一度流して確かめる。
